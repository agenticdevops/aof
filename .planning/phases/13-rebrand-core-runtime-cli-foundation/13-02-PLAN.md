  <name>Task 1: Write the Agent YAML v1 specification</name>
  <files>docs/spec/agent-yaml-v1.md</files>
  <action>
    Create `docs/spec/` directory if needed. Write the canonical Agent YAML specification document.

    The spec MUST include:

    **Top-level fields (Kubernetes-style):**
    ```yaml
    apiVersion: openagentix.dev/v1
    kind: Agent
    metadata:
      name: string (required, DNS-compatible: lowercase, alphanumeric, hyphens)
      namespace: string (optional, default: "default") — SPEC-04
      version: string (optional, semver format like "1.0.0") — SPEC-05
      labels: map[string]string (optional)
      annotations: map[string]string (optional)
    spec:
      # ... agent configuration
    ```

    **spec fields (all from SPEC-02 + CONTEXT.md decisions):**

    - `model`: string, required. Format: `provider/model` (e.g., `anthropic/claude-sonnet-4-6`, `openai/gpt-4o`, `google/gemini-2.0-flash`, `ollama/llama3`). Can be inherited from workspace defaults.
    - `mode`: enum, optional, default `autonomous`. Values: `manual`, `semi-autonomous`, `autonomous`. (Determines approval requirements — implemented in Phase 20, but defined now.)
    - `system_prompt`: string, optional. Inline system prompt text.
    - `system_prompt_file`: string, optional. Path to a .md file containing the system prompt. Mutually exclusive with `system_prompt`.
    - `max_iterations`: integer, optional, default 10. Maximum ReAct loop iterations before the agent stops.
    - `timeout`: string, optional, default "5m". Maximum wall-clock time for a single run (e.g., "30s", "5m", "1h").
    - `tools`: list, optional. Unified tool list. Each entry has:
      - `name`: string, required
      - `type`: enum (`cli`, `mcp`, `shell`), required
      - For `cli` type: `command` (string), `args` (list of strings), `description` (string)
      - For `mcp` type: `server` (string — server name from mcp_servers), `description` (string)
      - For `shell` type: `command` (string — shell command template), `description` (string)
    - `mcp_servers`: list, optional. MCP server configurations:
      - `name`: string, required
      - `transport`: enum (`stdio`, `sse`, `http`), required
      - `command`: string (for stdio)
      - `args`: list of strings (for stdio)
      - `url`: string (for sse/http)
      - `env`: map[string]string (optional, environment variables)
    - `triggers`: list, optional. (Defined in Phase 15 but the field exists now as placeholder.)
      - `type`: enum (`cron`, `webhook`, `github`, `jira`, `mention`, `agent`, `manual`)
      - Additional fields per trigger type
    - `notifications`: list, optional. Where to send run results.
      - `channel`: enum (`slack`, `telegram`, `discord`, `email`, `webhook`)
      - `target`: string (channel ID, chat ID, URL, email address)
    - `approval`: object, optional. (Defined in Phase 20.)
      - `required_for`: list of action patterns
      - `approvers`: list of approver identities
      - `timeout`: string
    - `budget`: object, optional. (Defined in Phase 17.)
      - `daily_limit`: string (e.g., "$0.50")
      - `max_tokens_per_run`: integer
    - `telemetry`: object, optional. (Defined in Phase 18.)
      - `enabled`: boolean
      - `exporter`: string
    - `env`: map[string]string, optional. Environment variables available to the agent's tools.

    **Include examples:**
    1. Minimal agent (just name + model + system_prompt)
    2. Full-featured agent with tools, MCP servers, and all optional fields
    3. Agent referencing an external system prompt file

    **Validation rules** (document these):
    - `metadata.name` must match regex `^[a-z][a-z0-9-]*[a-z0-9]$`, max 63 chars
    - `metadata.namespace` same format as name
    - `spec.model` must contain exactly one `/` separator
    - `system_prompt` and `system_prompt_file` are mutually exclusive
    - `max_iterations` must be 1-100
    - `timeout` must match duration format (e.g., "30s", "5m", "1h")
  </action>

<task type="auto">
  <name>Task 2: Write the workspace configuration specification</name>
  <files>docs/spec/workspace-config.md</files>
  <action>
    Write the workspace-level configuration specification for `agentix.yaml`.

    Per CONTEXT.md decision: workspace-level defaults in `agentix.yaml` — agents inherit `model`, `max_iterations`, etc. unless they override.

    **File: `agentix.yaml` (in workspace root)**

    ```yaml
    apiVersion: openagentix.dev/v1
    kind: Workspace
    metadata:
      name: string (workspace name)
    spec:
      defaults:
        model: string (default model for all agents, e.g., "anthropic/claude-sonnet-4-6")
        max_iterations: integer (default: 10)
        timeout: string (default: "5m")
        mode: enum (default: "autonomous")
      providers:
        anthropic:
          api_key: string or env ref (e.g., "${ANTHROPIC_API_KEY}")
        openai:
          api_key: string or env ref
        google:
          api_key: string or env ref
        ollama:
          base_url: string (default: "http://localhost:11434")
      gateway:
        host: string (default: "127.0.0.1")
        port: integer (default: 7777)
      agents_dir: string (default: "./agents")
    ```

    **Inheritance rules:**
    - Agent spec fields override workspace defaults
    - If agent omits `model`, workspace default is used
    - If workspace also omits `model`, error at validation time
    - Provider API keys can use `${ENV_VAR}` syntax for environment variable expansion
    - Provider config is workspace-only (not per-agent)

    **Environment variable expansion:**
    - `${VAR_NAME}` syntax in string values
    - Applied at load time
    - Missing env var → validation error with helpful message

    Document the resolution order:
    1. Agent YAML field (highest priority)
    2. Workspace defaults (agentix.yaml)
    3. Built-in defaults (lowest priority)

    Include examples:
    1. Minimal workspace config (just model + one provider)
    2. Full workspace config with all providers and gateway settings
  </action>
  <verify>
    <automated>test -f docs/spec/workspace-config.md && grep -q "agentix.yaml" docs/spec/workspace-config.md && grep -q "defaults:" docs/spec/workspace-config.md && echo "Workspace spec complete"</automated>
  </verify>
  <done>Workspace configuration spec document exists with defaults, provider config, gateway config, inheritance rules, and env var expansion docs.</done>
