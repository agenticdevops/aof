    Implement `ReActEngine` in react_loop.rs:

    ```rust
    pub struct ReActEngine {
        model: Arc<dyn Model + Send + Sync>,
        tool_executor: Arc<dyn ToolExecutor + Send + Sync>,
        config: ReActConfig,
        event_tx: Option<tokio::sync::broadcast::Sender<ReActEvent>>,
    }

    impl ReActEngine {
        pub fn new(model: Arc<dyn Model + Send + Sync>, tool_executor: Arc<dyn ToolExecutor + Send + Sync>, config: ReActConfig) -> Self

        pub fn with_event_stream(mut self, tx: tokio::sync::broadcast::Sender<ReActEvent>) -> Self

        /// Primary entry point: run an agent against a user input
        pub async fn run(&self, definition: &AgentDefinition, input: &str) -> Result<RunResult, AgentixError>
    }
    ```

    `ReActConfig` is built from AgentDefinition:
    ```rust
    impl ReActConfig {
        pub fn from_definition(def: &AgentDefinition) -> Self {
            Self {
                max_iterations: def.max_iterations,
                timeout: Duration::from_secs(def.timeout_secs),
            }
        }
    }
    ```

    The loop logic in `run()`:

    ```
    1. Build system prompt: definition.resolved_system_prompt()
    2. Prepend ReAct instructions to the system prompt:
       ---
       You are an AI agent operating in a ReAct (Reason + Act) loop.

       For each step:
       1. Plan: Analyze the current situation and decide what to do next
       2. Act: Call a tool if needed, or provide your final answer
       3. Observe: Review the tool result
       4. Reflect: Decide if you need another step or if you have the answer

       When you have enough information, respond without calling any tools.
       ---
    3. Initialize conversation messages: [system: <assembled prompt>, user: <input>]
    4. Start tokio::time::timeout(config.timeout, async { loop })
    5. For each iteration (1..=max_iterations):
       a. [Plan] Call model.complete(messages) — get LLM response
       b. Parse response:
          - If response.tool_calls is non-empty → [Act] for each tool call:
              i. Find ToolEntry in definition.tools by name
              ii. Call tool_executor.execute(tool_entry, tool_call.input)
              iii. Collect result (ok) or error text (err) — both are observations
          - If response.tool_calls is empty → loop ends with final answer
       c. [Observe] Format all tool results into observation text
       d. [Reflect] Append assistant message + tool results to conversation
       e. Create ReActStep { plan: response.text, action: first_tool_call, observation: obs_text, reflection: "" }
       f. Emit ReActEvent::Step(step) to event_tx if present
    6. If max_iterations reached without final answer: return RunResult { reached_max_iterations: true, ... }
    7. Emit ReActEvent::Complete(result)
    8. Return RunResult
    ```

    Key implementation details:
    - Tool execution: look up ToolEntry by name from `definition.tools`. If tool not found, return observation "Error: Tool '{name}' not found in agent definition". Never panic.
    - Tool failure is an observation, not an error. The string "Tool 'kubectl' failed: {error}" is appended to messages as a user/tool-result message. The loop continues.
    - `ToolExecutor::execute` is called with the ToolEntry and the JSON input from the LLM tool call.
    - `Model::complete` returns a `ModelResponse` with `text: String` and `tool_calls: Vec<ToolCall>`. Use `ToolCall { name: String, input: serde_json::Value }`.
    - Use `tokio::sync::broadcast::Sender` for the event stream. Use `send()` — if no receivers, that's fine (silently dropped).
