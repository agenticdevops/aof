**quickstart/agents/scheduled-reporter.yaml** — an agent that runs weekly to generate a report:

```yaml
apiVersion: openagentix.dev/v1
kind: Agent
metadata:
  name: scheduled-reporter
  description: Generates a weekly operational summary every Monday at 9 AM UTC
spec:
  model: anthropic/claude-3-haiku-20240307
  system_prompt: |
    You are a weekly operations reporter. When triggered by the cron scheduler,
    generate a concise operational summary covering system health, recent incidents,
    and action items. Keep the summary under 500 words.
  triggers:
    - type: cron
      expression: "0 9 * * 1"
  notifications:
    - type: webhook
      url: ${SLACK_WEBHOOK_URL}
  mode: autonomous
  max_iterations: 3
```

**quickstart/agents/github-pr-reviewer.yaml** — an agent triggered by GitHub PR events:
```yaml
apiVersion: openagentix.dev/v1
kind: Agent
metadata:
  name: github-pr-reviewer
  description: Automatically reviews pull requests when opened
spec:
  model: anthropic/claude-3-5-sonnet-20241022
  system_prompt: |
    You are a code review assistant. When a GitHub pull request is opened,
    review the PR description and provide constructive feedback on:
    - Clarity of the description
    - Potential risks or missing test coverage mentions
    - Suggestions for improvement
    Keep reviews concise and actionable.
  triggers:
    - type: github

      events:
        - pull_request
  mode: autonomous
  max_iterations: 5
```

```markdown
## v2.0.0-alpha.3 (2026-03-13)

### Added
- **Triggers + Scheduling** (Phase 15 — TRIG-01 through TRIG-11)
- Cron trigger: agents fire automatically on cron schedules (`triggers: [{type: cron, expression: "0 9 * * 1"}]`)
- Webhook trigger: generic HTTP POST at `/webhooks/:trigger_id` fires an agent
- GitHub trigger: HMAC-verified GitHub webhook fires agents on PR/push/tag events
- Jira trigger: Jira webhook fires agents on issue_updated/comment_created events
- Channel mention trigger: @mentioning the agent in Slack, Discord, or Telegram fires it
- Agent-to-agent trigger: one agent can fire another via `/api/v1/agents/:name/trigger`
- CLI trigger: `agentix run <agent> --input "..."` for one-shot manual execution
- `TriggerTrait` pluggable interface in agentix-core — add new trigger types without modifying core
- `TriggerEvent` envelope type with source, payload, context, fired_at, trigger_id
- `TriggerRegistry` for managing all active triggers at gateway level
- Run persistence: every agent run is stored in SQLite with trigger_source, timestamps, and status
- `agentix runs` now shows TRIGGER column with trigger source for each run
- Notification routing: webhook notifications dispatched after triggered runs complete
- Quickstart examples: `scheduled-reporter.yaml` and `github-pr-reviewer.yaml`

### New concepts docs
- `docs/concepts/triggers.md` — trigger system overview
- `docs/concepts/cron-triggers.md` — cron scheduling
- `docs/concepts/webhook-triggers.md` — HTTP webhooks
- `docs/concepts/run-persistence.md` — run history and SQLite storage
- `docs/guides/github-integration.md` — GitHub webhook setup
- `docs/guides/jira-integration.md` — Jira webhook setup
- `docs/guides/triggers-quickstart.md` — 5-minute trigger quickstart
```
