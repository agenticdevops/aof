Create `crates/agentix/src/commands/audit.rs` implementing `agentix audit <agent-name>`.

**Command structure (kubectl-style):**
```
agentix audit <agent-name>              # Show last 50 audit entries
agentix audit <agent-name> --limit 100  # Show last 100 entries
agentix audit <agent-name> --security   # Show security events only
agentix audit <agent-name> --run <id>   # Filter to specific run
```

**Implementation:**

Use clap for argument parsing, consistent with existing CLI commands.

```rust
#[derive(clap::Args)]
pub struct AuditArgs {
    /// Agent name to show audit trail for
    pub agent_name: String,

    /// Maximum number of entries to show
    #[arg(long, default_value = "50")]
    pub limit: u32,

    /// Show security events only (violations, denials, blocks)
    #[arg(long)]
    pub security: bool,

    /// Filter to a specific run ID
    #[arg(long)]
    pub run: Option<String>,
}
```

**Handler `execute_audit(args: AuditArgs, ctx: &CliContext)`:**

1. Connect to the gateway API:
   - If `--security`: GET `{gateway_url}/api/v1/audit/security?limit={limit}`
   - If `--run`: GET `{gateway_url}/api/v1/agents/{name}/runs/{run_id}/audit` (or filter client-side)
   - Otherwise: GET `{gateway_url}/api/v1/agents/{name}/audit?limit={limit}`

2. Parse the JSON response into Vec<AuditEntry>.

3. Display as a formatted table:
```
TIMESTAMP            EVENT TYPE          ACTION                              OUTCOME
2026-03-13 12:00:05  tool_call          kubectl get pods -n production       success
2026-03-13 12:00:03  llm_call           anthropic/claude-sonnet-4-6     success
2026-03-13 12:00:01  agent_start        Starting agent run run-789           success
2026-03-13 11:59:55  security_violation SSRF blocked: 169.254.169.254        blocked
```

Use ANSI colors for outcomes: green for success, red for failure/blocked/denied.

4. Wire into main.rs:
   - Add `Audit(AuditArgs)` variant to the top-level CLI command enum
   - Dispatch to `execute_audit()` in the match arm

```yaml
apiVersion: openagentix.dev/v1

metadata:
  name: secure-workspace

  agents_dir: agents/

    anthropic:
      api_key: ${ANTHROPIC_API_KEY}
  security:
    ssrf_protection: true
    secret_encryption: true
    audit_enabled: true
    allowed_private_endpoints:
      - "10.0.0.5"     # Internal Prometheus
      - "172.16.1.10"   # Internal Grafana

    max_iterations: 10
    timeout: 300
```

```markdown
## v2.0.0-alpha.7 (2026-03-13) — Security Infrastructure

### Added
- **SSRF Protection** (SEC-05): SsrfGuard blocks HTTP tool calls to RFC 1918 private IPs, localhost (127.0.0.1, ::1), and cloud metadata endpoints (169.254.x.x). Configurable allow-list for internal services.
- **Secret Encryption** (SEC-03): AES-256-GCM encryption for secrets at rest via SecretStore. SecretRedactor prevents secret values from appearing in logs, traces, or error output.
- **Audit Trail** (SEC-04): SQLite-backed AuditStore logs every tool call, LLM call, and security event with actor, timestamp, outcome, and details. REST API endpoints for querying audit data.
- **WASM Capability Enforcement** (SEC-01, SEC-02): WasmToolExecutor now reads capabilities from tool YAML manifests. Undeclared capability access is blocked and logged as a security violation.
- **CLI**: `agentix audit <agent-name>` command with `--security`, `--run`, and `--limit` flags.
- **REST API**: GET /api/v1/agents/:name/audit, GET /api/v1/audit/security endpoints.
- **Configuration**: `security:` block in workspace agentix.yaml for SSRF, encryption, and audit settings.
- **Documentation**: Security concepts guide, CLI audit reference, security setup tutorial, quickstart example.

### Changed
- ReAct loop now integrates SSRF guard, secret redactor, and audit logging for every tool and LLM call.
- WasmToolExecutor parses capabilities from ToolEntry instead of defaulting to empty.
- AgentManager passes SecurityConfig to ReActEngine via ReActConfig.
```
