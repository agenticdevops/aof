Add the following endpoints to api.rs and wire them in router.rs:

**GET /api/v1/approvals** — List pending approval requests.
- Query params: `agent` (optional filter by agent name), `limit` (optional, default 50)
- Returns 200 with JSON array of ApprovalRequest objects
- If `agent` is specified, calls `approval_store.get_pending_by_agent(agent)`
- Otherwise calls `approval_store.list_pending(limit)`

**GET /api/v1/approvals/:request_id** — Get a single approval request.
- Returns 200 with the ApprovalRequest if found
- Returns 404 with ErrorResponse if not found

**POST /api/v1/approvals/:request_id/approve** — Approve a pending request.
- Request body: `{ "approver": "admin@company.com" }`
- Retrieves the request from ApprovalStore
- If not found: returns 404
- If not Pending: returns 409 Conflict with "Request already decided"
- If Pending: calls update_status with Approved, logs audit entry, returns 200 with updated request

**POST /api/v1/approvals/:request_id/deny** — Deny a pending request.
- Request body: `{ "approver": "admin@company.com", "reason": "Too risky" }` (reason optional)
- Same flow as approve but sets Denied status
- Returns 200 with updated request

Wire all four routes in router.rs:
```rust
.route("/api/v1/approvals", get(list_approvals))
.route("/api/v1/approvals/:request_id", get(get_approval))
.route("/api/v1/approvals/:request_id/approve", post(approve_request))
.route("/api/v1/approvals/:request_id/deny", post(deny_request))
```

Update the API doc header comment in api.rs to include the new endpoints.

Run `cargo check --workspace` and confirm it compiles.
