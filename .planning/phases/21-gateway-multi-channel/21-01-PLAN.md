Create `docs/concepts/multi-channel-gateway.md` covering:

1. **Overview** — OpenAgentiX supports bi-directional multi-channel communication. Agents receive messages from Slack, Telegram, and Discord channels and respond in the same channel. Agents can also send outbound notifications (run results, alerts, approval requests) to configured channels without a user-initiated trigger.

2. **Supported Platforms** — Table with Slack, Telegram, Discord. For each: features supported (messages, threads, rich formatting, notifications), authentication method (bot token + signing secret / bot token / bot token + public key).

3. **Channel Configuration** — Document the `spec.channels` section of `agentix.yaml`:
   ```yaml
   spec:
     channels:
       - platform: slack
         credentials:
           platform: slack
           bot_token: "${SLACK_BOT_TOKEN}"
           signing_secret: "${SLACK_SIGNING_SECRET}"
           app_id: "A12345"
         routes:
           - channel_id: "C_DEVOPS"
             agent_name: dba-optimizer
             direction: bidirectional
           - channel_id: "C_ALERTS"
             agent_name: cost-anomaly-detector
             direction: outbound
         enabled: true
   ```

4. **Routing** — Explain per-channel agent routing:
   - `inbound` — Messages in this channel trigger the specified agent
   - `outbound` — Agent can send notifications to this channel but won't receive messages
   - `bidirectional` — Both inbound triggers and outbound notifications (default)
   - Multiple routes per channel config (different channels -> different agents)
   - Agent name must match a loaded agent in the gateway

5. **Notification System** — Document outbound notification payloads:
   - Notification severity levels (info, warning, error, critical)
   - When notifications fire: run completion, budget exceeded, approval needed, errors
   - Notification target: platform + channel_id + optional thread_id

6. **Message Flow** — Document the bi-directional flow:
   - Inbound: Platform webhook -> Gateway -> Route to agent -> ReAct loop -> Response -> Platform
   - Outbound: Agent produces result/alert -> NotificationPayload -> ChannelGateway -> Platform API

7. **Security** — Webhook signature verification per platform. Credential storage via environment variables.

8. **CLI Preview** — `agentix channels` to list configured channels and their routes.
