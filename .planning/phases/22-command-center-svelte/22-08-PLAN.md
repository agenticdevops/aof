  <action>
    1. Create `src/lib/stores/settings.ts`:
       - `hasCompletedWizard` writable store: reads from localStorage key `'agentix-wizard-complete'`, defaults to `false`
       - `completeWizard()`: sets store to true, persists to localStorage
       - `resetWizard()`: sets store to false, clears localStorage key
       - `settings` writable store: `{ gatewayUrl: string; theme: 'light' | 'dark' | 'system'; refreshInterval: number }` read from localStorage

    2. Create `src/lib/components/wizard-step.svelte`:
       - Reusable step component for the wizard
       - Props: `title: string`, `description: string`, `stepNumber: number`, `totalSteps: number`, `active: boolean`
       - Shows step indicator (numbered circle), title, description
       - Renders slot content for step-specific UI
       - Footer: "Back" and "Next"/"Finish" buttons

    3. Create `src/lib/components/first-run-wizard.svelte`:
       - Full-screen overlay modal with centered card (max-w-2xl)
       - Progress bar at top showing current step / total steps
       - 4 steps:

         **Step 1: Welcome**
         - "Welcome to OpenAgentiX Command Center" heading
         - Brief intro: "Let's get you set up to monitor and manage your AI agents."
         - OpenAgentiX logo or icon
         - Just a "Get Started" button

         **Step 2: Connect to Gateway**
         - Gateway URL input (pre-filled with current gatewayUrl store value)
         - "Test Connection" button: calls `api.health.check()`, shows green checkmark on success or red error on failure
         - Explanation: "Enter the URL of your running agentix gateway (usually http://localhost:7777)"
         - On success, save URL via `setGatewayUrl()`

         **Step 3: Explore**
         - Show how many agents are registered (fetch from gateway on step enter)
         - If agents exist: "You have N agents registered. Explore them on the dashboard."
         - If no agents: "No agents registered yet. You can create one in the Agent Builder."
         - Quick links: "Go to Dashboard" / "Open Agent Builder"

         **Step 4: Done**
         - "You're all set!" celebration message
         - Quick summary of what's available: Dashboard, Agents, Costs, Traces, Approvals, Builder
         - "Open Dashboard" button that calls `completeWizard()` and closes overlay

       - Closable: X button in corner (marks wizard as completed)
       - Exports: `onclose` callback

    4. Update `src/routes/+layout.svelte`:
       - Import `hasCompletedWizard` store
       - Conditionally render FirstRunWizard overlay when `$hasCompletedWizard === false`
       - On wizard close/complete, hide overlay

    5. Create `src/routes/settings/+page.svelte`:
       - Page title: "Settings" with Settings icon
       - Sections:
         - **Gateway Connection**: URL input, test connection button, connection status indicator
         - **Appearance**: Theme selector (light/dark/system)
         - **Onboarding**: "Re-launch Setup Wizard" button (calls `resetWizard()`, then shows wizard)
         - **About**: App version, gateway version (from /healthz if available), links to docs
       - Save button: persists all settings to localStorage

    6. The sidebar already links to /settings from Plan 01. The scheduler view is part of the main navigation. However, since there is no dedicated scheduler API endpoint in the gateway, the "Scheduler" view will be built from agent data:
       - Scheduler view is NOT a separate route — instead, add a "Scheduled" tab/section to the Agents page or create a minimal `/runs` sub-section.
       - Actually, per the requirements (CMD-06: "Scheduler view shows cron schedules and upcoming runs"), create a simple section on the dashboard or a filtered view:
         - In the agents store, filter agents that have `triggers` with `type: 'cron'`
         - Show each scheduled agent with: agent name, cron expression, human-readable schedule (e.g., "Every Monday at 9 AM"), last run time, next run time (computed from cron expression)
         - For cron parsing, install `cron-parser` package: `npm install cron-parser`
       - Add this as a "Scheduled Agents" card on the dashboard landing page (in the quick panels area alongside "Active Runs" and "Pending Approvals").
       - This keeps the scheduler view integrated rather than isolated on a separate page.
