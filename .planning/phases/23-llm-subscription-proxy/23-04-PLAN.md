Add four new endpoints to the gateway API. Register them in `create_api_routes()` in api.rs:

```rust
// Auth/OAuth endpoints (Phase 23)
.route("/api/v1/auth/:provider/start", get(auth_start))
.route("/api/v1/auth/:provider/callback", get(auth_callback))
.route("/api/v1/auth/:provider/status", get(auth_status))
.route("/api/v1/auth/:provider", delete(auth_disconnect))
```

**GET /api/v1/auth/:provider/start:**
- Extract provider from path param, normalize with `normalize_provider()`
- For OpenAI: generate PKCE state, build authorize URL, store PKCE state temporarily in a `DashMap<String, PkceState>` on the AuthState (keyed by state param). Return `{"auth_url": "https://...", "provider": "openai"}`. Then spawn a background task that calls `receive_loopback_code()` on port 1455 — when code arrives, exchange for tokens and store via AuthService.
- For Gemini: same pattern but port 1456, needs client_id/client_secret from env vars
- For Anthropic: Return instructions to paste setup-token. If user provides a token, it's stored directly via `/api/v1/auth/anthropic/token` (POST). Actually, the simpler approach for Anthropic: the start endpoint returns `{"auth_url": null, "provider": "anthropic", "method": "token", "instructions": "Paste your Claude setup-token or API key"}` — the UI handles the token input directly.

**Important architectural note on loopback:** The loopback server approach from zeroclaw (spawn TCP listener on :1455/:1456) works for CLI flows. For Command Center browser flows, the callback can instead redirect back to the gateway's `/api/v1/auth/:provider/callback` endpoint. Choose the approach that works for both CLI and UI:
- CLI: `agentix auth start <provider>` opens browser, spawns loopback listener, exchanges code
- UI: Command Center opens popup to authorize URL, OAuth provider redirects to gateway callback endpoint

The gateway callback endpoint approach is cleaner for the UI flow. For CLI, the loopback server approach works. The gateway needs to handle BOTH — the callback endpoint handles the UI flow, and the loopback code for CLI is handled by the CLI binary (plan 05). For now, implement the gateway callback endpoint for UI flows.

**GET /api/v1/auth/:provider/callback:**
- Extract `code` and `state` from query params
- Look up PKCE state from the DashMap using the `state` param
- Exchange code for tokens (OpenAI or Gemini)
- Store tokens via AuthService
- Return HTML redirect back to Command Center settings: `<script>window.close()</script>` (for popup flow) or redirect to `/settings?auth=success`

**GET /api/v1/auth/:provider/status:**
- Load profiles from AuthService
- Find active profile for provider
- Return: `{"provider": "...", "authenticated": true/false, "mode": "oauth"|"token", "expires_at": "ISO8601"|null, "account_id": "..."|null, "needs_reauth": true/false}`
- `needs_reauth` = true if token is expired and refresh failed

**DELETE /api/v1/auth/:provider:**
- Remove the active profile for the provider via AuthService
- Return 204 No Content

**Also add POST /api/v1/auth/:provider/token for Anthropic (and as fallback for others):**
- Accepts `{"token": "..."}` body
- For Anthropic: detect auth kind, store via `store_provider_token()`
- For OpenAI/Gemini: store as OAuth token if it looks like a JWT, or as API key otherwise

**Shared state:** Add an `AuthState` struct (or extend existing router state) to hold:
- `auth_service: Arc<AuthService>`
- `pending_pkce: Arc<DashMap<String, PkceState>>` (temporary storage during OAuth flows, entries expire after 10 min)

Thread this through axum state. The simplest approach is to add AuthService to AgentManager.

2. **Modify `create_provider_from_definition()` to use subscription tokens:**
In the existing function, after resolving `provider_overrides` and before creating the model, check if the provider is configured in subscription mode:

```rust
// After resolving api_key and endpoint from overrides/config/env:
// Check workspace config for subscription mode
let provider_mode = workspace_config
    .as_ref()
    .and_then(|wc| wc.spec.providers.get(provider_name))
    .and_then(|pc| pc.mode.as_ref())
    .cloned();

if matches!(provider_mode, Some(ProviderMode::Subscription)) {
    // Get OAuth token from AuthService
    if let Some(auth_service) = auth_service {
        let token = match provider {
            ModelProvider::OpenAI => auth_service.get_valid_openai_access_token(None).await?,
            ModelProvider::Google => auth_service.get_valid_gemini_access_token(None).await?,
            ModelProvider::Anthropic => auth_service.get_provider_bearer_token("anthropic", None).await?,
            _ => None,
        };
        if let Some(token) = token {
            api_key = Some(token);
            // Set provider_mode in extra for factory routing
            model_config.extra.insert("provider_mode".to_string(), serde_json::json!("subscription"));
        } else {
            return Err(AgentixError::Config(format!(
                "Provider {} is configured for subscription mode but no OAuth token found. Run `agentix auth start {}`",
                provider_name, provider_name
            )));
        }
    }
}
```

Note: The function signature may need to become async if it isn't already, since `get_valid_*_access_token` are async (they may need to refresh tokens). If the function is sync, pass the token in from the caller which is already async.
